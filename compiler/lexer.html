Lexer

A lexer (also called a tokenizer or scanner) converts a sequence of characters into a sequence of tokens, which are the smallest units of meaning in a programming language. It is the first phase of a compiler: it reads the raw source text and identifies elements such as identifiers, operators and keywords, so that the later phases can work with those instead of individual characters.

source text → lexer → tokens → parser → AST

Lexeme and token

A lexeme is the exact text found in the source, for example count or ==. A token is what the lexer produces for it: a category (identifier, operator, ...), the lexeme itself, and its position in the file.

Key roles

  • Tokenization: takes the source text and turns it into meaningful tokens.
  • Skipping what the parser does not need: whitespace and comments are recognized and discarded.
  • Tracking positions: every token remembers its line and column, so later phases can report precise errors.
  • Reporting lexical errors: unknown characters, unterminated strings and malformed numbers are detected here.
  • First phase of compilation: it prepares the input for the parser.

Kinds of tokens

Tokens usually fall into categories such as:

  • Identifiers (e.g., variable and function names)
  • Keywords (e.g., if, else, return, for, and type names such as int and float)
  • Literals (e.g., 42, 3.14, "text")
  • Operators (e.g., +, -, *, ==)
  • Grouping symbols and separators (e.g., parentheses, brackets, braces, ;)

Source code

The lexer is written in C and is open source. The code, the documentation comments in the headers and the test suite are available on GitHub: github.com/RobloxCode/lexer.

Get it and build it

git clone https://github.com/RobloxCode/lexer.git
cd lexer
make

This builds the static library build/liblexer.a. A C11 compiler (GCC or Clang) and GNU make are required.

Use it from your own program

Include lexer/lexer.h and link against the library. With the repository cloned next to your main.c, no installation is needed: 

cc -std=c11 -Ilexer/include main.c lexer/build/liblexer.a -o app
./app some_file.c

The README in the repository explains the other option (installing the library system-wide or into ~/.local), how editors find the headers, and includes a complete example program.

Run the tests

cd lexer/tests
make test

Stages of lexing

  1. The lexer receives the source code and reads it from start to end, one character at a time, keeping track of the current position, line and column.
  2. At each step it looks at the current character and decides what kind of token starts there: an operator, a digit, a keyword or identifier, a string, etc.
  3. When several tokens could match, it takes the longest one (maximal munch): <= is a single token, not < followed by =.
  4. Once the type is known, the token is appended to the list of tokens (an array of Token).
  5. This continues until the end of the file (EOF), which is also stored as a token so the parser knows where the input ends.

Input and output

The lexer receives the source text and produces a list of tokens. For the input int x = 3 + 5; it produces:

# Token type Lexeme Line:Column
1KEYWORDint1:1
2IDENTIFIERx1:5
3OPERATOR=1:7
4NUMBER31:9
5OPERATOR+1:11
6NUMBER51:13
7PUNCT;1:14
8EOF1:15

Token types

The lexer recognizes 102 token types, grouped into delimiters, operators, literals, keywords (C89 and C99/C11) and a few special tokens for end of input and errors. See the full list of token types.

Token

Macros
#define TOKEN_BUF_MAX_CAP 255
TOKEN_BUF_MAX_CAP
Maximum capacity that every word can have.
typedef struct {
    TokenType type;
    char lexeme[TOKEN_BUF_MAX_CAP];
    int line;
    int column;
} Token;

Represents a single token found in the source text.

Members
type
The kind of token (see TokenType).
lexeme
Lexeme of the current token in the source code.
line, column
Position of the first character, counting from 1.
Notes

No lexeme can be longer than TOKEN_BUF_MAX_CAP, otherwise you will have overflow errors.

Example
Token token = {
    .type = TOK_IDENTIFIER,
    .line = 1,
    .column = 1
};

strcpy(token.lexeme, "count");

printf("%s\n", token.lexeme);
count

void token_init(Token *t, const StrBuf *word, const int line, const int col);

Sets the values of the token t. It determines which type the token has by classifying the resulting lexeme.

Parameters
t
Pointer to a stack allocated Token.
word
String buffer storing the word being tokenized.
line

col

lexer_lex

Lexer *lexer_lex(const char *path);

Lexes the file at the given path.

Parameters
path
Path of the file to be lexed.
Return value

Pointer to a heap allocated Lexer. The tokens produced are stored in its tokens member.

Notes

The returned lexer must be freed with lexer_deinit.

Example
Lexer *l = lexer_lex("main.c");

/* l->tokens now holds the tokens of main.c */

lexer_deinit(&l);

Problems


            
Lexing multi-character operators


            

              Many operators are made of several characters, and the
              shorter ones are prefixes of the longer ones:
              <, << and
              <<= all start the same way. If the
              lexer matches the shortest operator first, it stops at
              < and splits <<= into
              three tokens.
            


            

              The approach used here is to check from the longest
              candidate to the shortest: first the three characters
              cur, peek and peek2,
              then the two characters cur and
              peek, and only then cur alone.
              The first operator that matches is the biggest one, which
              is the maximal munch rule. This is also the
              reason the lexer needs two characters of lookahead.
            


            
Lexing numbers


            

              A number is not just a run of digits, and a few details
              have to be checked while it is being built:
            


            
    
              
  • 
                Decimal points: 3.14 is
                one number, but 1.2.3 is malformed. The
                lexer has to remember whether it has already seen a
                point. A . followed by a digit
                (.5) starts a number, while a lone
                . is an operator.
              
    • 
              
  • 
                Suffixes: literals such as
                10u, 10UL and
                3.14f carry a suffix that is part of the
                same lexeme. After the digits, the lexer accepts the
                valid suffix letters.
              
    • 
              
  • 
                Letters that do not belong: something
                like 12abc is not a number followed by an
                identifier, so it is reported as an invalid token.
