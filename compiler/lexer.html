Lexer

A lexer (also called a tokenizer or scanner) converts a sequence of characters into a sequence of tokens, which are the smallest units of meaning in a programming language. It is the first phase of a compiler: it reads the raw source text and identifies elements such as identifiers, operators and keywords, so that the later phases can work with those instead of individual characters.

source text → lexer → tokens → parser → AST

Lexeme and token

A lexeme is the exact text found in the source, for example count or ==. A token is what the lexer produces for it: a category (identifier, operator, ...), the lexeme itself, and its position in the file.

Key roles

  • Tokenization: takes the source text and turns it into meaningful tokens.
  • Skipping what the parser does not need: whitespace and comments are recognized and discarded.
  • Tracking positions: every token remembers its line and column, so later phases can report precise errors.
  • Reporting lexical errors: unknown characters, unterminated strings and malformed numbers are detected here.
  • First phase of compilation: it prepares the input for the parser.

Kinds of tokens

Tokens usually fall into categories such as:

  • Identifiers (e.g., variable and function names)
  • Keywords (e.g., if, else, return, for, and type names such as int and float)
  • Literals (e.g., 42, 3.14, "text")
  • Operators (e.g., +, -, *, ==)
  • Grouping symbols and separators (e.g., parentheses, brackets, braces, ;)

Stages of lexing

  1. The lexer receives the source code and reads it from start to end, one character at a time, keeping track of the current position, line and column.
  2. At each step it looks at the current character and decides what kind of token starts there: an operator, a digit, a keyword or identifier, a string, etc.
  3. When several tokens could match, it takes the longest one (maximal munch): <= is a single token, not < followed by =.
  4. Once the type is known, the token is appended to the list of tokens (an array of Token).
  5. This continues until the end of the file (EOF), which is also stored as a token so the parser knows where the input ends.

Token

#include <stddef.h>

typedef struct {
    TokenType type;
    const char *start;
    size_t length;
    int line;
    int column;
} Token;

Represents a single token found in the source text.

Members
type
The kind of token (see TokenType).
start
Pointer to the first character of the lexeme inside the source text. The text is not copied.
length
Number of characters in the lexeme.
line, column
Position of the first character, counting from 1.
Notes

Because start points into the source text, the source must stay alive for as long as its tokens are used.

Example
Token token = {
    .type = TOKEN_IDENTIFIER,
    .start = "count = 1;",
    .length = 5,
    .line = 1,
    .column = 1
};

printf("%.*s\n", (int) token.length, token.start);

lexer_init

void lexer_init(Lexer *lexer, const char *source);

Prepares lexer to scan source, starting at line 1, column 1.

Parameters
lexer
Pointer to the lexer to initialize.
source
Null-terminated source text. It is not copied, so it must outlive the lexer.

lexer_next_token

Token lexer_next_token(Lexer *lexer);

Skips whitespace and comments, scans the next token and returns it. Once the end of the source is reached, every call returns a token of type TOKEN_EOF.

Parameters
lexer
Lexer previously prepared with lexer_init.
Return value

The next token. An unknown character produces a token of type TOKEN_ERROR instead of stopping the lexer.

Example
Lexer lexer;
lexer_init(&lexer, "int x = 3 + 5;");

Token token;

do {
    token = lexer_next_token(&lexer);

    printf("%d:%-3d %-11s %.*s\n",
           token.line, token.column,
           token_type_name(token.type),
           (int) token.length, token.start);
} while (token.type != TOKEN_EOF);
